# Platform extension: setup, operations and limits

Updated 19 November 2026. This release extends the existing Next.js 16.4.6 / React 19.3 / TypeScript / Tailwind 4 app, Neon Postgres + Neon Auth and Vercel. It retains direct ipcam.kz playback, weather, events, the catalog, menus, planner, CRM and existing approval/inventory protections. RTSP.me remains removed.

## Where to work

| Route                                   | Who / purpose                                                                                                                                           |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/admin/hub`                            | Owner/manager requests and clients, pipeline, quotes, catalog, menus, events and analytics; partners see assigned menus only                            |
| `/admin/research`                       | Owner: independent research drafts, field evidence, bilingual source text, permitted official price finder and review queue                             |
| `/admin/guides`                         | Owner/manager: guide calendars, workload, matching, offers, completion approval, reviews and follow-up proposals; owner controls profiles/rates/invites |
| `/admin/payments`                       | Owner: payment links, discount/voucher codes, actual cash receipts/refunds, card refund requests, transfer ledger, policies, deals and operation logs   |
| `/admin/updates`, `/admin/cameras`      | Existing source jobs, failure alerts, API/source status and camera management                                                                           |
| `/guides`, `/guides/[id]`               | Public active guide profiles and approved reviews; no fictional guides are seeded                                                                       |
| `/guide`                                | Invited, verified guide: offers, availability, accepted tours and earnings                                                                              |
| `/checkout/[request-id]?plan=[plan-id]` | Client's dedicated private quote, codes, terms and hosted payment/arrival choices                                                                       |
| `/payment/[request-id]?plan=[plan-id]`  | Private payment state and PDF acknowledgments; refreshes briefly after return from Stripe                                                               |
| `/tour/[request-id]?plan=[plan-id]`     | Private trip, day route, weather, chat, photos, check-ins, bot pairing, reviews and follow-up requests                                                  |
| `/deals`, `/account`                    | Published deals, confirmed service alerts, returning-traveller codes and referral credit                                                                |
| `/ui-states`                            | Light/dark interactive component reference; noindex                                                                                                     |

Use the verified owner email already allowed by `OWNER_EMAILS`. New guides must sign in and verify the invited address, then accept their private invitation and guide terms. Invitations expire after 14 days. An existing owner/manager/partner role cannot be replaced by an invitation. Anonymous travellers retain separate public share and private edit capabilities; never send a private link to anyone except its traveller.

## Install, migrate, test, deploy

Use Node 22. Run `npm ci`, copy `.env.example` to `.env.local`, fill the existing database/auth/origin settings and run `npm run db:migrate`. Migrations are additive and rerunnable. `006-platform.sql` adds ledgers, guide roles and transaction functions. Back up or branch the database before migrating an established installation. Never run integration fixtures against production.

Run `npm test`, `npm run typecheck`, `npm run build`, then `npm run dev` or `npm start`. For the supplied integration scripts, use a separate Neon branch with `INTEGRATION_BRANCH=platform-v2-test-2026-11-19` in gitignored `.env.platform-test`, no live provider keys, and `node --env-file=.env.platform-test --import tsx scripts/test-platform-integration.ts`. The script removes its test records and uses mocked Stripe methods. It does not verify a real Stripe account, send a real email or transfer real funds.

Vercel: import this repository, Node 22, Next.js preset, root directory at the repository root, `npm run build`. Existing project/domain remain `https://almaty-travel-guide.vercel.app`. Keep all keys in Production environment variables and redeploy after changes. Netlify uses the existing Next.js adapter configuration; change workflow target URLs and auth allowed origins to your chosen host. This is a server-rendered application, not a static export.

## How money and guides work

The manager's quote is a final, tax-inclusive package total in its settlement currency. New quotes snapshot tax/fee decomposition and cancellation terms. Settings do not retroactively rewrite accepted quotes. Catalog/group/seasonal/bounded weekday adjustments affect estimates; they are not added a second time to the final quote. Unknown prices stay unknown. Currency switching is display-only and uses dated indicative rates.

Clients approve the current plan/quote and accept checkout terms. Promo is calculated before voucher; usage and voucher balances are reserved under database locks for 35 minutes. Stripe sessions expire after 30 minutes. Expired or changed reservations require reapplying codes. Prices and payable amounts come from the server, never the browser. A deposit is a percentage of the net total, less recorded payments. Catalog services can require a minimum card deposit percentage, enforced when the manager quotes. Established packages can settle an outstanding balance after completion without making a new reservation. Duplicate events, refunds and completion transfers use durable ledger/provider IDs.

Use **Create & email payment link** to queue a private checkout link. **Open WhatsApp draft** opens the owner's own messaging app; no message is sent automatically. Actual outbound delivery requires the configured provider. Gift vouchers are owner-issued credit, not an online gift-voucher store. Codes are immutable once created.

Cash receipt/refund actions record money the owner actually received/returned; they do not move provider funds. Card cancellation uses the policy accepted with the quote, reverses relevant guide transfers first, and waits for signed refund confirmation. Cash/voucher adjustments require actual owner accounting. Network-uncertain refunds show `needs-review`; inspect the same ledger/provider record instead of blindly creating another refund. PDF documents are payment/cash acknowledgments, not statutory tax invoices. Supply legal operator/tax details and use suitable local accounting for compliant invoicing.

Guide offers snapshot the fee and commission. Matching uses preference, language, specialty, availability, review rating and rate; unknown ratings are not invented. Open calendar coverage is required for the whole trip interval, including overnight intervals in a multi-day package. Offers default to 30 minutes, with failover on decline/expiry. Database locks prevent conflicting offers/acceptances. Use the manager's cancellation/reassignment process for accepted trips; pausing prevents new offers but does not erase obligations.

Guide self-completion is a request. A manager approves only after the scheduled end. The transfer worker waits the configured delay, requires a completed package, full confirmed funds and an active eligible Connect account. Cash/voucher-only earnings are manual accounting. A Stripe transfer credits the recipient balance; bank payout timing is Stripe's responsibility. No real payment, refund, account onboarding or bank payout was performed during development.

## Automation and caching

Existing workflows target 05:00 Almaty for daily content, hourly weather and 15-minute camera checks. `platform-operations.yml` runs at UTC minutes 4/19/34/49 for offer failover, eligible earnings, waitlist alerts, loyalty, daily owner/client-bot digests and price watches. GitHub schedules are best effort and can be delayed; a strict real-time SLA needs a dedicated scheduler/queue. No Codex desktop session is required for these server jobs.

Daily owner digest is deduplicated by Almaty date after 05:00. It reports new requests, unpaid packages, tomorrow's tours, guide issues, weather cautions and camera problems. Owner **Run operations update now** and the existing source update controls are available. Jobs log successes/failures, preserve last-good snapshots, and queue the owner's Resend alert after consecutive failures. No sender key means visibly queued/configuration-required delivery, not a sent claim.

Wikipedia/Commons/OSM research and robots policies cache for 24 hours, requested translations for 24 hours, local-context AI answers for one hour, and road routes for 24 hours. Google Place IDs persist; other live Google details are intentionally not cached/copied into the catalog or sent to AI. Closed-place/changed-hours/accessibility OSM checks run weekly and produce owner review drafts; closure hiding follows the existing owner option. Permitted price watches check one due source per operations tick, with a 24-hour freshness target. Photos are purged 90 days after completed/cancelled trips. Bot pairing tokens expire after 15 minutes; webhook update IDs deduplicate delivery.

## Monthly planning estimate

Checked against provider pages on 19 November 2026; this is a budget scenario, not a quote. For a small commercial pilot, allow **about $20–$50/month for hosting + database + low-volume email**, plus the weather commercial plan, payment/Connect fees and any optional search/AI/WhatsApp/SMS usage. Vercel [Pro starts at $20/month](https://vercel.com/pricing); Hobby is for personal/noncommercial use. [Neon](https://neon.com/pricing) currently has a free allowance and usage-based Launch (published typical intermittent workload $15/month). [Resend](https://resend.com/pricing) allows 3,000 monthly/100 daily emails free, then $20/month for its 50,000 plan. Gallery storage and frequent scheduler calls can exceed free DB allowances.

[Tavily](https://docs.tavily.com/documentation/api-credits) supplies 1,000 free credits; this release uses basic one-credit searches. [Open-Meteo](https://open-meteo.com/en/pricing) requires its commercial plan for commercial operation; check its current subscription price. Google SKU, Stripe account-country fees and AI model pricing vary: set provider budgets/quotas before enabling them. No paid plan was activated in this release.

## Validation and practical limits

Automated checks cover token contrast, source URL/IP/robots rules, structured prices, pricing bounds, private access, scheduling races, promo/voucher reservations/expiry, hosted-session reuse, duplicate payment/refund events, private photo re-encoding/access, guide commission transfer/reversal and cash-ledger idempotency. The production build and API/SSR smoke checks are separate from browser interaction testing.

The saved CUA security policy rejected localhost browser preview. It explicitly prohibited alternate browser/headless/alternate-origin workarounds. Consequently this release has **no claimed before/after browser screenshots, axe score, Lighthouse score or visual regression pass**. The `/ui-states` gallery and contrast calculations are available; browser QA remains to be performed when that policy allows it. PDF pages were rendered and visually inspected independently.

Before accepting real customers, use actual sandbox/provider credentials to test: invite/verified login for each role; guide offer/decline/timeout and multi-day calendar; approved quote/deposit/balance/arrival; wallet eligibility; card decline/late webhook/refund/reversal; country onboarding/transfer/bank payout; email sender/alerts; Telegram pairing/replay/unlink; WhatsApp signature/template/24-hour window; gallery authorization/retention; mobile keyboard and light/dark states; assistant/translation consent; source permissions and billing quotas.

Remaining scope limits: research cannot promise complete coverage or every requested field/photo/price. Live Google is a separate reference panel; it is not a licence to scrape/copy. Public reviews are owner-moderated completed-trip reviews. Guide follow-ups currently create manager-reviewed new requests requiring a final quote, rather than an automatic one-click repurchase. Deals request an owner-confirmed quoted discount; no automatic capacity promise. New platform screens are primarily English; the existing EN/RU site, bilingual sourced descriptions and EN/RU assistant remain. The offline pack uses a labelled schematic per-day map, not downloaded street tiles. Private galleries are intentionally small DB-backed galleries, not a high-volume media service.
