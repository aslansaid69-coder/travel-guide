# Обновление ноября 2026: админ-панель, места, туры, оплата, ИИ-помощник

## 1. Как войти как владелец (OWNER)

1. В Vercel → Project → Settings → Environment Variables должен быть `OWNER_EMAILS` с вашим адресом
   (сейчас `aslansaid69@gmail.com`). Несколько адресов — через запятую.
2. Откройте `https://<ваш-домен>/auth/sign-in`, введите этот email, нажмите «Send sign-in code».
3. Введите 6-значный код из письма. Вас перенаправит в `/admin`.
4. Роль OWNER выдаётся **только** по `OWNER_EMAILS` на сервере. Её нельзя получить или снять через интерфейс.
   Если убрать адрес из `OWNER_EMAILS`, права владельца пропадают при следующем запросе.

**Админов (ADMIN), гидов и партнёров** назначаете вы: человек сначала один раз входит по email (становится TOURIST),
затем вы открываете **Admin → Users & roles** и выбираете роль. Все смены ролей пишутся в **Audit log**.

| Роль | Что может |
| --- | --- |
| OWNER | всё, включая гидов, цены, настройки помощника, возвраты, роли |
| ADMIN | места (импорт/редактирование/публикация), брони, отзывы, диалоги помощника, журнал |
| GUIDE | кабинет гида `/guide` (свои туры, календарь, заработок) |
| TOURIST | конструктор тура, брони, оплата, отзывы после поездки |

`/admin` закрыт трижды: `proxy.ts` (сессия + роль), layout админки (`requirePage`) и каждое серверное действие (`authorize`).

## 2. Переменные окружения для Vercel

Обязательные (уже должны быть): `DATABASE_URL`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_COOKIE_SECRET`, `OWNER_EMAILS`,
`NEXT_PUBLIC_SITE_URL`, `CRON_SECRET`.

Новые / важные для обновления:

| Переменная | Зачем | Пример |
| --- | --- | --- |
| `DATABASE_URL_UNPOOLED` | прямое (не pooled) подключение Neon для миграций | `postgres://…ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require` |
| `ANTHROPIC_API_KEY` | ИИ-помощник и «Сгенерировать описание» (только сервер) | `sk-ant-…` |
| `ANTHROPIC_MODEL` | необязательно, модель Claude | `claude-opus-5-5` |
| `GOOGLE_PLACES_API_KEY` | импорт мест, фото, часы, отзывы Google (Places API **New**, ключ с ограничением по API) | |
| `OPENTRIPMAP_API_KEY` | бесплатная альтернатива Google (необязательно) | |
| `PLACES_PROVIDER` | провайдер по умолчанию: `google` / `opentripmap` / `wikipedia` | пусто = первый доступный |
| `STRIPE_SECRET_KEY` | оплата; по умолчанию **тестовый** ключ | `sk_test_…` |
| `STRIPE_WEBHOOK_SECRET` | подпись вебхука Stripe | `whsec_…` |
| `PAYMENTS_LIVE` | `true` разрешает боевой ключ `sk_live_…`; иначе он блокируется | `false` |
| `PAYMENT_PROVIDER` | `stripe` (место для будущего локального провайдера) | `stripe` |
| `RESEND_API_KEY`, `ALERT_FROM`, `ALERT_TO` | письма туристам и уведомления владельцу об оплате | |
| `ORS_API_KEY` | (необязательно) дорожные маршруты OpenRouteService в старом планировщике | |

Полный список с комментариями — `.env.example`. После изменения переменных — **Redeploy**.

Stripe webhook: `https://<домен>/api/payments/webhook`, события: `checkout.session.completed`,
`checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`,
`refund.created`, `refund.updated` (+ существующие события travel-desk из `docs/PLATFORM-SETUP.md`).

## 3. Миграции на продакшене

Миграции теперь версионные: таблица `schema_migrations` хранит имя и checksum каждого применённого файла.
Новые файлы: `009-roles-audit.sql`, `010-places.sql`, `011-tours-reviews.sql`. Все аддитивные и идемпотентные.

1. **Проверка на ветке Neon.** В консоли Neon создайте ветку от `main` (например `upgrade-2026-11`), скопируйте её
   строку подключения в `.env.local` (`DATABASE_URL` и `DATABASE_URL_UNPOOLED`), затем:
   ```bash
   npm ci
   npm run db:migrate:status   # покажет 009, 010, 011 (и 001–008 при первом трекинге — это безопасно)
   npm run db:migrate
   ```
   Откройте preview-деплой, проверьте страницы из раздела 5.
2. **Продакшен.** Сделайте бэкап/ветку Neon от `main`, затем с продакшен-строкой подключения:
   ```bash
   DATABASE_URL="<prod pooled>" DATABASE_URL_UNPOOLED="<prod direct>" npm run db:migrate:prod
   ```
   Затем смёржите PR → Vercel задеплоит код. Код совместим со старой схемой ролей (`manager` читается как `admin`),
   поэтому порядок «миграция → деплой» безопасен.
3. Если файл миграции изменили после применения, раннер остановится с ошибкой — нужно создать новый файл.

## 5. Что проверить вручную

1. Вход владельцем → `/admin`: дашборд, блок Setup (все ключи «OK»).
2. **Users & roles**: второй email входит как турист, вы назначаете ADMIN → у него открывается `/admin`, но нет «Pricing», «Users» (owner-only).
3. **Places → Add place**: поиск «Central State Museum» (Wikipedia без ключа или Google с ключом) → Import →
   «Generate description» → проверить RU/EN/KZ текст → Status = Published → Save → открыть `/places/<slug>`.
4. Для места из Google: фото, адрес и часы видны с подписью Google; в базе только place ID и координаты (кнопка «Refresh coordinates» раз в 30 дней).
5. **Pricing**: задайте свой тариф за км, комиссию, предоплату; пример справа пересчитывается.
6. **Guides** (owner): заполните гида (ставка «Per day», регионы `Almaty, Almaty Region`, языки, опыт, статус active) и календарь доступности.
7. `/build`: выберите 3–4 места → цена «≈ от X до Y» с разбивкой, карта маршрута, расстояние/время → дата → гид → войти → подтвердить.
8. Оплата тестовой картой `4242 4242 4242 4242` → бронь становится **Paid** (через вебхук) → в админке Bookings: Confirm → Complete.
9. После Complete турист видит на странице места форму отзыва; отзыв появляется после одобрения в **Reviews**.
10. ИИ-помощник (кнопка «Ask a local»): спросить по-русски «Сколько стоит Кок-Тобе и Шымбулак на двоих?» — ответ со стримингом,
    цена из расчёта, предложение добавить в тур. В **Assistant** видны диалог, можно править промпт и выключать помощника.
11. Без `ANTHROPIC_API_KEY` помощник отвечает понятной ошибкой, а кнопка генерации описаний неактивна.
12. Телефон: `/build`, `/places/kok-tobe`, `/admin` (меню админки прокручивается горизонтально).

## 7. Чем выделиться среди Wanderlog, visitalmaty.kz, Tripadvisor и GetYourGuide

Уже есть в продукте:
- **Честная цена с разбивкой** до бронирования (билеты × люди, км × тариф, гид × дни, комиссия) с источником и датой каждой цены — у конкурентов цена либо фиксированного «пакета», либо её нет.
- **Только проверенные отзывы** («Подтверждённая поездка») рядом с живыми отзывами Google.
- **ИИ-планировщик на собственных данных**: не выдумывает цены, сам добавляет места в маршрут.
- **Живые камеры и прогноз погоды** на главной (у вас уже есть) — уникально для Алматы.
- **Три языка (RU/EN/KZ)**, тенге по умолчанию, местные гиды с календарём.

Идеи на следующий шаг:
1. **Погодный «план Б»**: если на дату тура в горах дождь/ветер — помощник и конструктор сами предлагают замену (музей, Кок-Тобе) по данным уже работающего погодного модуля.
2. **Kaspi Pay / Halyk ePay** как второй платёжный провайдер (интерфейс `PaymentProvider` готов) — главное преимущество перед GetYourGuide для местных и гостей из СНГ.
3. **Живая очередь на канатку / заполненность** по камерам ipcam.kz («сейчас мало людей на Шымбулаке»).
4. **Офлайн-маршрут** (PWA уже есть): карта и билеты доступны без интернета в горах.
5. **Групповой тур с разделением оплаты**: друзья присоединяются к брони по ссылке и платят свою часть.
6. **Telegram-бот** с теми же инструментами помощника (бот-инфраструктура уже есть в `lib/platform/bots.ts`).
